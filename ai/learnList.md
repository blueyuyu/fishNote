# 总结
> 背景回顾你们整套链路：
> 桌面端Electron客户端 → MCP/Skill Agent(LangGraph) → Jev安全审核 → gVisor代码沙箱
> 后端：vLLM离线推理、异构A100/H100 GPU、多K8s集群、算力调度平台
> 核心研发主线：选定Harness路线RSI → 评测预测模型前置筛选 → 集群批量benchmark评测

## 🔴 第一优先级（立刻先补，开会高频，本周重点）【重中之重】
目标：听懂所有评审、MVP讨论、方案取舍，这是你现在最缺的
1. **Agent 基础体系（LangGraph、节点、状态流转、MCP、Skill、Harness外壳）**
    学：
    - LangGraph：节点、边、state、循环、human-in-the-loop（Human Gate）
    - Harness到底包含哪些东西（system prompt、记忆、工具、子Agent、安全规则）
    - MCP / Skill插件结构，一个skill目录里面有什么文件、怎么加载
    - 区分：Agent本身、Harness、基础大模型三者
    不用学：从零手写复杂Agent，会看流程图、看懂节点流转即可
2. **这套项目的安全链路：Jev + gVisor**
    一句话记忆：Jev是跑之前预审；gVisor是跑代码的沙箱笼子
    要懂：什么时候触发、风险是什么、隔离的意义
3. **评测体系（你们最近一直在推进：baseline、benchmark、成功率、评测质量、集群评测）**
    重点弄懂：
    - baseline是什么，为什么评测必须固定baseline
    - 评测怎么算成功，自动评测的局限
    - 预测模型的定位：不是打分，是预审筛掉坏改动，节省算力
    - RSI为什么极度依赖靠谱评测（裁判不准，RSI就跑偏）
    - 区分：全量评测（慢、真实）、预测模型（快、预筛选）

✅ 这周速成顺序：Agent概念 → Harness/MCP/Skill → 评测整套逻辑 → Jev+gVisor

## 🟠 第二优先级（紧接着补，集群/算力相关，开会天天出现）
目标：听懂部署侧讨论，异构卡、调度、K8s相关，不用你写运维脚本
1. GPU & 推理基础：A100/H100差异、显存、量化FP8、vLLM推理框架、算子
    重点：
    - A100不支持FP8，H100支持（异构集群最大痛点）
    - vLLM作用：PagedAttention加速推理，离线模型部署
    - 算子：GPU专用高速计算单元，不同卡算子不通用
2. K8s、多集群、算力调度平台（CubeStudio这类）
    弄懂：
    - 单K8s vs 多K8s集群为什么拆分（业务集群 / 实验评测集群隔离）
    - 算力调度平台的作用：管异构GPU、优先级、资源隔离，防止评测抢占线上推理
    - 知道：评测任务是低优先级，线上推理是高优先级
    不用学：kubectl命令精通、写yaml、运维排障

## 🟡 第三优先级（RSI核心逻辑，方案评审用，理解即可，不用实现）
RSI你们选定路线：**Harness级递归自改进（不改模型权重）**
重点吃透这套闭环：
1. RSI循环：Agent生成新Harness/Skill → 预测模型预审 → 通过才上集群跑正式benchmark → 拿到真实分数 → 回传优化预测模型
2. 对比另一条路线：权重级RSI（微调模型，成本高、风险大，你们MVP暂时不选）
3. RSI最大坑：评测污染、预测模型偏差、Agent学会“刷评测分数”

## 🟢 第四优先级（浅了解，按需再深挖，现阶段不用花大量时间）
- Loss、训练、微调、DPO：知道名词含义就行，你们MVP不走权重微调路线

- 离线大模型、GGUF量化：知道离线=不上传数据，本地/机房GPU跑推理
- 前端侧：Electron桌面端和Agent后端的交互（SSE、接口调用，这个是你本职，你本来就熟）
